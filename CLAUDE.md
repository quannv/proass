# PRODUCT OVERVIEW
ProActive Assistant is a real-time meeting companion. When the user turns it on during a group discussion or meeting:
1. It captures live audio from the microphone (and optionally from a browser tab, for online meetings).
2. It transcribes speech to text in real time using **Muse Voice Transcribe** (STT).
 - Document: https://dev.meta.ai/docs/speech-to-text
3. It continuously analyzes the conversation and **proactively** surfaces relevant, helpful information in a side panel, generated by Muse Wonder (LLM, model id `muse-wonder-1.0`), without the user having to ask.

Goal: help the user follow, understand, and contribute to the conversation, e.g. explain unfamiliar terms, provide background facts, clarify acronyms, suggest smart questions to ask, and capture decisions and action items.

# IMPORTANT: API INTEGRATION RULES
- Do NOT guess endpoints, parameters, auth headers, or response formats for Muse Voice Transcribe or the Muse LLM. Ask me for the official docs or SDK, or leave clearly marked TODOs.
- Wrap each external service behind an interface (adapter pattern):
  - `STTProvider`: `start(stream)`, `stop()`, events `onPartial(text)`, `onFinal(segment)`, `onError(err)`
  - `LLMProvider`: `generateSuggestions(context): Promise<Suggestion[]>`, with streaming support if the API allows it
- Provide a `MockSTTProvider` (replays a scripted transcript with realistic timing) and a `MockLLMProvider` so the full app works end-to-end before real keys are connected.
- API keys must live only on the server (environment variables). Never expose them to the browser.
- Model choice: the LLM is `muse-wonder-1.0` (Standard only, so prompts are not used for training), set via the `MUSE_LLM_MODEL` env var (never hard-coded). `muse-spark-1.3` is the faster, cheaper fallback; verified 2026-11-01 that Wonder accepts the same request shape (strict json_schema, `developer` role, `reasoning_effort: minimal`).
- Known API facts (from https://dev.meta.ai/docs):
  - STT streaming: `wss://api.meta.ai/v1/asr/realtime`; auth token goes in the first handshake frame (`authorization.accessToken`), not an HTTP header. Audio: mono 16-bit PCM, 24 kHz preferred (16 kHz allowed). Partials in `CUMULATIVE` or `DELTA` mode; finals via `speechComplete`; diarization supported; turn-level timestamps only; max 60 min per session.
  - LLM: `POST https://api.meta.ai/v1/chat/completions`, `Authorization: Bearer <key>`. Structured output via `response_format: { type: "json_schema", json_schema: { name, schema, strict: true } }` (constrained decoding; strict mode needs `additionalProperties: false`, no `oneOf`/`allOf`).
  - STT handshake also accepts `keywords` (string[]) and `languageBias` (language names). Handshake ack is `{"sessionId": ...}` with no `type`; `speaker` events arrive just before `speechComplete`.
  - Chat completions is OpenAI-compatible: `developer` role, `reasoning_effort` (`minimal|low|medium|high|xhigh`; Muse models always reason, `none` is a 400), `max_completion_tokens` (includes reasoning tokens), SSE streaming via `stream: true` (`data: {...}` … `data: [DONE]`). `stop`, `n>1` and `logprobs` are unsupported.
  - Tools (verified live on muse-wonder-1.0, 2026-11-01; the docs claim otherwise): function tools on chat completions work together with strict `response_format` json_schema; `tool_choice` only accepts `"auto"`; `parallel_tool_calls: false` works; dropping `tools` on the final call (with tool history present) is fine. Built-in search is `tools: [{"type":"web_search"}]` on `POST /v1/responses` (`reasoning: {effort}`, `instructions`, `input`, `max_output_tokens`); it returns no citations/annotations, and the answer is the last `message` item in `output` (earlier ones are preambles).

# CORE PIPELINE
1. **Audio capture**: Start/Stop toggle, mic level meter, device selector, permission error handling.
2. **Streaming STT**: Send audio chunks to the server, which forwards them to the STT provider. Display partial (gray, live-updating) and final (solid) transcript lines with timestamps. Show speaker labels if the STT supports diarization; otherwise omit them.
3. **Context manager**:
   - Keep a rolling window of the last ~2–3 minutes of final transcript.
   - Maintain a running meeting summary (refreshed every few minutes by the LLM) so long meetings stay within the context limit.
   - Track suggestions already shown to avoid repeats.
4. **Trigger logic** (when to call the LLM): call after a meaningful new chunk of final text (e.g. ≥ 25 words or a natural pause of ~2 s), with debouncing, a minimum interval (e.g. 8–10 s), and cancellation of stale in-flight requests. Make all thresholds configurable.
5. **Suggestion generation**: The LLM returns structured JSON (schema below). Validate it with Zod and drop malformed or low-confidence items.
6. **Suggestion panel**: New cards slide in at the top, each with a type badge, a short title, 1–3 sentence body, and the transcript snippet that triggered it (click to scroll to that moment in the transcript). Actions: pin, dismiss, copy, "tell me more" (on-demand deeper explanation).

# SUGGESTION SCHEMA
{
  "suggestions": [
    {
      "type": "definition" | "background" | "fact_check" | "question_to_ask" | "action_item" | "decision" | "related_idea",
      "title": "string (max 8 words)",
      "body": "string (max 50 words)",
      "trigger_quote": "short exact quote from the transcript",
      "confidence": 0.0-1.0
    }
  ]
}
Return an empty array when nothing is genuinely useful. Silence is better than noise.

# LLM SYSTEM PROMPT (use inside the app)
"You are ProActive Assistant, a silent, helpful companion listening to a live meeting. Based on the recent transcript and the meeting summary, surface at most 3 high-value, concise insights that help the user understand or contribute right now. Focus on: unfamiliar terms or acronyms, useful background context, claims that may need verification, insightful questions the user could ask, and decisions or action items. Do not repeat items from the 'already shown' list. Do not restate what was just said. If you are not confident a fact is correct, either mark it with low confidence or omit it; never invent numbers, names, or sources. Respond in the same language as the conversation. Output only valid JSON matching the schema."
